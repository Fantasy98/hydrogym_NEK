# Nek-HydroGym Examples

This directory contains examples for running transient simulations with Nek5000 using the HydroGym framework. The examples demonstrate how to use classical Active Flow Control (AFC) controllers and integrate with reinforcement learning workflows.

## Overview

The nek-hydrogym integration provides:
- **Transient simulation** of Nek5000 environments
- **Classical AFC controllers** (Opposition Control, Blowing/Suction, Sinusoidal waves)
- **SB3 model integration** for trained RL policies
- **History recording** of observations, actions, and rewards
- **MPI-based execution** for parallel Nek5000 simulations

## Directory Structure

```

├── exec-script           # Bash script for running simulations with MPI

        └── env_00*/      # Evaluation runs
```

## Quick Start

### 1. Initialize Run Folder

First, initialize the run folder structure:

```bash
mpirun -n 1 python3 nek_initial.py --config conf/MC-OC.yml
```

This creates the necessary folder structure and writes the run path to `dir-files/RUN_PATH_{agent_run_name}.txt`.

### 2. Run Simulation

#### Option A: Using exec-script (Recommended)

The `exec-script` handles MPI setup and folder initialization automatically:

```bash
# Single run
./exec-script --mode run --config MC-OC.yml --steps 1000

# Evaluation mode (multiple environments)
./exec-script --mode eval --config MC-OC.yml --nenvs 6 --steps 1000

# With config overrides
./exec-script --mode run --config MC-OC.yml \
    --overrides "runner.ctrl_max_amp=0.5" "runner.rank=1"
```

#### Option B: Direct Python Execution

```bash
# Run with default settings
mpirun -n 1 python3 run-transient.py --config conf/MC-OC.yml \
    : -n 10 bash -c "cd runs/1998/env_001 && ./nek5000"

# With overrides and controller type
mpirun -n 1 python3 run-transient.py \
    --config conf/MC-OC.yml \
    --overrides "runner.rank=1" "runner.evaluation=True" \
    --ctrl_type OC \
    --steps 1000 \
    : -n 10 bash -c "cd runs/1998/env_001 && ./nek5000"
```

## Configuration Files

Configuration files use YAML format with two main sections:

### `runner` Section
- `agent_run_name`: Unique identifier for the run (e.g., `1998`)
- `RL_algorithm`: Controller type (`"OC"`, `"BL"`, `"SIN"`, `"ZERO"`, or RL algorithm name)
- `ctrl_max_amp`: Maximum control amplitude
- `nb_interactions`: Number of simulation steps
- `nb_episodes`: Number of episodes
- `rank`: MPI rank for evaluation mode
- `evaluation`: Boolean flag for evaluation mode
- `vars_record`: Enable history recording (default: `True`)
- `vars_record_freq`: Frequency of recording (default: `1`)

### `simulation` Section
- `CASENAME`: Nek5000 case name
- `nproc`: Number of MPI processes for Nek5000
- `dt`: Time step
- `tmax`: Maximum simulation time
- `restart_folder`: Path to restart data

Example configuration (`conf/MC-OC.yml`):
```yaml
runner:
  agent_run_name: 1998
  RL_algorithm: "OC"
  ctrl_max_amp: 1.0
  nb_interactions: 2500
  evaluation: True
  rank: 1
  vars_record: True
  vars_record_freq: 1

simulation:
  CASENAME: "phill"
  nproc: 10
  dt: -1.0e-2
  tmax: 100000.0
```

## Controller Types

### Classical AFC Controllers

The framework supports several classical Active Flow Control strategies:

#### 1. Opposition Control (`OC`)
Opposes the flow velocity:
```python
action = -alpha * observation[1, 0, 0]
```

#### 2. Blowing/Suction (`BL`)
Steady uniform blowing/suction:
```python
action = alpha
```

#### 3. Sinusoidal Wave (`SIN`)
Sinusoidal wave control based on spatial coordinates.

#### 4. Zero Control (`ZERO`)
No control (baseline):
```python
action = 0.0
```

### Using Controllers

Controllers are automatically created based on the `RL_algorithm` setting in the config:

```python
from hydrogym.nek import make_afc_controller

# Create controller from environment
controller = make_afc_controller(env, ctrl_type="OC")
```

### Using SB3 Models

You can also use trained Stable-Baselines3 models directly:

```python
from stable_baselines3 import PPO

# Load trained model
model = PPO.load("path/to/model")

# Pass directly to integrate (it has .predict() method)
hgym.integrate(env, t_span=(0, T_final), controller=model)
```

## History Recording

The framework automatically records observations, actions, and rewards when `vars_record: True` is set in the config.

### Output Format

History files are saved as `.mat` files in the rank folder:
```
runs/{agent_run_name}/env_{rank:03d}/vars_record_{timestamp}.mat
```

The `.mat` file contains a dictionary with per-agent data:
```python
{
  'agent_0': {
    'obs_rec': array([...]),  # Observations
    'act_rec': array([...]),  # Actions
    'rew_rec': array([...])   # Rewards
  },
  'agent_1': { ... },
  ...
}
```

### Loading History

```python
import scipy.io as sio

# Load recorded data
data = sio.loadmat('runs/1998/env_001/vars_record_1234567890.mat')

# Access agent data
obs = data['agent_0']['obs_rec']
actions = data['agent_0']['act_rec']
rewards = data['agent_0']['rew_rec']
```

## Command-Line Options

### `run-transient.py`

- `--config`: Path to YAML configuration file (required)
- `--overrides`: Config overrides (e.g., `"runner.rank=1" "runner.evaluation=True"`)
- `--steps`: Number of simulation steps (overrides config)
- `--ctrl_type`: Controller type (`"OC"`, `"BL"`, `"SIN"`, `"ZERO"`)

### `exec-script`

- `--config`: Configuration file name (e.g., `MC-OC.yml`)
- `--mode`: Execution mode (`run` or `eval`)
- `--steps`: Number of steps
- `--nenvs`: Number of environments for eval mode (default: 6)
- `--compile`: Compile the Nek5000 case before running
- `--script`: Python script name (default: `run-transient.py`)
- `--overrides`: Config overrides (space-separated)

## Examples

### Example 1: Run Opposition Control

```bash
# Initialize
mpirun -n 1 python3 nek_initial.py --config conf/MC-OC.yml

# Run
./exec-script --mode run --config MC-OC.yml --steps 1000
```

### Example 2: Evaluate Multiple Environments

```bash
./exec-script --mode eval --config MC-OC.yml --nenvs 6 --steps 1000
```

This creates 6 separate runs in `runs/1998/env_001` through `runs/1998/env_006`.

### Example 3: Use Trained RL Model

```python
from stable_baselines3 import PPO
import hydrogym.nek as hgym

# Load model
model = PPO.load("runs/1998/logs/model.zip")

# Create environment
env = hgym.NekMARLGymWrapper(conf=conf, reward_agg="mean")

# Run with RL controller
hgym.integrate(env, t_span=(0, 100), controller=model)
```

### Example 4: Custom Controller

```python
def my_controller(t, obs, env):
    """Custom control law"""
    return np.array([0.5 * np.sin(t)], dtype=np.float32)

hgym.integrate(env, t_span=(0, 100), controller=my_controller)
```

## Troubleshooting

### Issue: Files saved to wrong location

Ensure `nek_initial.py` runs before `run-transient.py` to create the correct folder structure. The run path is stored in `dir-files/RUN_PATH_{agent_run_name}.txt`.

### Issue: MPI errors

Make sure OpenMPI is properly configured and the environment variables are set (see `exec-script` for required setup).

### Issue: Controller not found

Check that `RL_algorithm` in the config matches one of the supported types, or use `--ctrl_type` to override.

## Advanced Usage

### Custom Callbacks

```python
from hydrogym.nek.utils.io import LogCallback

def postprocess(env):
    reward = getattr(env, 'last_reward', 0.0)
    return reward, 0.0

callback = LogCallback(
    postprocess=postprocess,
    nvals=1,
    interval=10,
    filename="my_log.dat"
)

hgym.integrate(env, t_span=(0, 100), callbacks=[callback])
```

### Environment Wrappers

The framework supports both:
- `NekMARLGymWrapper`: Concatenated observations/actions (Gym-style)
- `parallel_env`: Dictionary-based observations/actions (PettingZoo-style)

Both work seamlessly with the `integrate()` function and controllers.
